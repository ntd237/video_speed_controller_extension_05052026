## Root Cause Analysis Report

### Executive Summary

**Issue**: Overlay hiển thị tốc độ không khớp với tốc độ phát thực tế khi chuyển sang video mới

**Primary Root Cause**: Khi video mới được thêm vào DOM, hàm `handleNewVideo()` chỉ áp dụng tốc độ từ storage (`settings.currentSpeed`) nhưng không cập nhật overlay để hiển thị tốc độ thực tế của video mới. Overlay được tạo với tốc độ từ storage, nhưng video mới có playbackRate mặc định là 1x, dẫn đến desync.

**Severity**: Medium - Tính năng hoạt động nhưng hiển thị sai, gây nhầm lẫn người dùng

**Occurrence**: Deterministic - Xảy ra mỗi khi chuyển sang video mới sau khi đã thay đổi tốc độ

**Impact Scope**: Tất cả video trên các trang web được hỗ trợ

### Detailed Root Cause Analysis

#### Root Cause #1: Overlay được tạo với tốc độ từ storage thay vì tốc độ thực tế của video

**Likelihood**: 99% (High - Confirmed by code analysis)

**Category**: Logic Error - State Desynchronization

**Evidence Found**:

1. **Code location**: `content/content.js:229-241` - Hàm `handleNewVideo()`
   ```javascript
   function handleNewVideo(video, settings) {
     if (processedVideos.has(video)) {
       return;
     }

     if (settings.autoApply) {
       applySpeedToVideo(video, settings.currentSpeed, settings);
     } else {
       // Vẫn tạo overlay nhưng không áp dụng tốc độ
       updateOverlay(video, video.playbackRate || DEFAULTS.currentSpeed, settings);
       processedVideos.add(video);
     }
   }
   ```

2. **Code location**: `content/content.js:193-206` - Hàm `applySpeedToVideo()`
   ```javascript
   function applySpeedToVideo(video, speed, settings) {
     try {
       const clampedSpeed = clampSpeed(speed);
       video.playbackRate = clampedSpeed;

       // Tạo hoặc cập nhật overlay
       updateOverlay(video, clampedSpeed, settings);

       // Đánh dấu video đã được xử lý
   ```

3. **Code location**: `content/content.js:139-169` - Hàm `updateOverlay()`
   ```javascript
   function updateOverlay(video, speed, settings) {
     let overlay = videoOverlayMap.get(video);

     // Tạo overlay mới nếu chưa tồn tại hoặc bị xóa khỏi DOM
     if (!overlay || !overlay.isConnected) {
       overlay = createOverlay(video, speed, settings);
   ```

**Explanation**:

Khi `autoApply` được bật (mặc định là true), hàm `handleNewVideo()` gọi `applySpeedToVideo()` với `settings.currentSpeed`. Hàm này:
1. Set `video.playbackRate = clampedSpeed` (tốc độ từ storage)
2. Gọi `updateOverlay()` với tốc độ này
3. Overlay được tạo với nội dung hiển thị tốc độ từ storage

**Tuy nhiên**, vấn đề xảy ra khi:
- Người dùng phát video A ở tốc độ 2x
- Tốc độ 2x được lưu vào `chrome.storage.sync.currentSpeed`
- Người dùng chuyển sang video B (video mới được thêm vào DOM)
- MutationObserver phát hiện video B mới
- `handleNewVideo()` được gọi với video B
- `applySpeedToVideo()` set `video.playbackRate = 2x` (từ storage)
- Overlay được tạo hiển thị "2.0"

**Nhưng** nếu video B là một video khác trên YouTube (ví dụ: click vào video khác trong danh sách), YouTube có thể:
1. Tái sử dụng video element cũ hoặc tạo video element mới
2. Reset playbackRate về 1x trước khi content.js kịp áp dụng tốc độ
3. Hoặc có delay giữa khi video element được thêm vào DOM và khi nó sẵn sàng nhận playbackRate

**Mechanism** (Cơ chế xảy ra):

1. Người dùng phát video A ở 2x → `currentSpeed = 2x` được lưu vào storage
2. Người dùng click video B trên YouTube
3. YouTube thay đổi DOM, video element mới được thêm vào
4. MutationObserver phát hiện (line 262-289)
5. `handleNewVideo()` được gọi với video B mới
6. `applySpeedToVideo()` set `video.playbackRate = 2x` (từ storage)
7. Overlay được tạo hiển thị "2.0"
8. **NHƯNG**: YouTube hoặc trình duyệt reset playbackRate về 1x sau khi content.js áp dụng
9. **HOẶC**: Có race condition - video element chưa sẵn sàng khi playbackRate được set
10. Kết quả: Overlay hiển thị "2.0" nhưng video chạy ở "1x"

**Impact Analysis**:

  - MutationObserver callback
- **User Impact**: Người dùng nhầm lẫn, không biết video đang chạy ở tốc độ nào

**Reproduction Conditions**:

  - Tốc độ đã được lưu vào `chrome.storage.sync.currentSpeed`

- **Trigger Actions**:

#### Root Cause #2: Race condition giữa MutationObserver và video element initialization

**Likelihood**: 60% (Medium - Possible contributing factor)

**Category**: Timing/Race Condition

**Evidence Found**:

1. **Code location**: `content/content.js:262-289` - MutationObserver callback
   ```javascript
   mutationObserver = new MutationObserver((mutations) => {
     const newVideos = [];
     mutations.forEach((mutation) => {
       if (mutation.type === 'childList') {
         mutation.addedNodes.forEach((node) => {
           if (node.nodeType === Node.ELEMENT_NODE) {
             if (node.tagName === 'VIDEO') {
               newVideos.push(node);
             }
             const videos = node.querySelectorAll('video');
             videos.forEach(video => {
               newVideos.push(video);
             });
           }
         });
       }
     });

     if (newVideos.length === 0) return;

     // Lấy settings mới nhất từ storage để tránh dùng closure cũ
     chrome.storage.sync.get(DEFAULTS, (settings) => {
       newVideos.forEach(video => {
         handleNewVideo(video, settings);
       });
     });
   });
   ```

2. **Issue**: Khi video element được thêm vào DOM, nó có thể chưa sẵn sàng hoàn toàn:
   - Thuộc tính `readyState` có thể chưa là `HAVE_METADATA` hoặc cao hơn
   - Playback engine có thể chưa được khởi tạo
   - Setting `playbackRate` trên video chưa sẵn sàng có thể bị ignore hoặc reset

3. **Timing**: Có delay giữa khi `chrome.storage.sync.get()` được gọi (async) và khi `handleNewVideo()` thực thi, trong khi đó video element có thể đã được reset bởi trang web

**Explanation**:

MutationObserver phát hiện video element được thêm vào DOM, nhưng video element có thể chưa sẵn sàng. Khi `applySpeedToVideo()` set `video.playbackRate`, nó có thể bị reset bởi:
1. Trình duyệt khi video element hoàn thiện initialization
2. Trang web (YouTube) khi nó setup video player
3. Video codec/engine khi nó khởi tạo

**Mechanism**:

1. YouTube thêm video element vào DOM
2. MutationObserver phát hiện ngay lập tức
3. `chrome.storage.sync.get()` được gọi (async)
4. Trong khi chờ storage callback, YouTube setup video player
5. YouTube set playbackRate về 1x (mặc định)
6. Storage callback trả về, `handleNewVideo()` được gọi
7. `applySpeedToVideo()` set playbackRate = 2x
8. **NHƯNG**: YouTube hoặc trình duyệt đã reset nó về 1x
9. Hoặc: Có race condition, YouTube reset sau khi content.js set

## Recommended Fix Approach

**Option 1 (Recommended)**: Sử dụng event listener thay vì MutationObserver

- Lắng nghe `loadedmetadata` hoặc `canplay` event trên video element
- Chỉ áp dụng tốc độ khi video sẵn sàng
- Đảm bảo overlay hiển thị tốc độ thực tế của video

**Option 2**: Thêm verification sau khi set playbackRate

- Sau khi set `video.playbackRate`, kiểm tra xem nó có được áp dụng không
- Nếu không, retry hoặc log warning

**Option 3**: Sử dụng `requestAnimationFrame` để delay việc áp dụng tốc độ

- Đảm bảo video element đã hoàn thiện initialization
- Có thể giải quyết race condition

## Conclusion

Root cause của bug là **logic error trong hàm `handleNewVideo()`** kết hợp với **race condition giữa MutationObserver callback và video element initialization**. Khi video mới được thêm vào DOM, overlay được tạo với tốc độ từ storage, nhưng video element có thể chưa sẵn sàng hoặc bị reset bởi trang web, dẫn đến desync giữa overlay display và actual playback rate.

Fix nên tập trung vào:
1. Phát hiện khi video element sẵn sàng (sử dụng event listener)
2. Áp dụng tốc độ chỉ khi video sẵn sàng
3. Cập nhật overlay với tốc độ thực tế của video, không phải từ storage
